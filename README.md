# wallswitch

定时换壁纸（桌面/锁屏）· 多壁纸库 · 小组件 · 开机自恢复定时

## 上屏方式（v2.0 起两种，自动选择）

- **引擎模式（推荐）**：把本 App 设为动态壁纸后，桌面由内置 `WallSwitchService`
  引擎直接解码渲染（借鉴 Muzei 的直接渲染方案，Canvas 实现）。不走系统静态壁纸链路，
  从架构上根治荣耀 MagicOS 的"幽灵图"（setBitmap 成功但 Launcher 回落兜底图）问题。
  主界面点「设为动态壁纸引擎」一键激活。
- **静态链路（兜底）**：引擎未激活时自动回退 `WallpaperManager.setBitmap` +
  三道校验 + 读回比对重试。用户被主题商店/杂志锁屏顶掉引擎后功能不中断。

- **v2.1**：界面重设计为 Material 3 简洁浅色风（卡片分区、圆角按钮、浅灰页面底），
  小组件同步改为白色卡片 + 品牌蓝图标；全面屏/刘海屏边到边适配（内容避开状态栏、
  刘海挖孔与底部手势条，修复 Android 15 强制 edge-to-edge 导致的顶部遮挡）；功能逻辑零改动。
  主界面排版改为「顶部头部 + 内容滚动区 + 底部固定操作坞」三段式：库/定时/引擎/壁纸列表
  四张卡片可滚动，「切换桌面/切换锁屏 + 添加壁纸」常驻底部拇指可达；全部控件 id/类型不变。

- **v3.0**：主界面结构重组为「顶栏 + 底部双 Tab（壁纸 / 设置）」。壁纸列表独立成页并拿到整屏高度，
  根治 v2.1「320dp 固定高列表套在外层 ScrollView 里」的嵌套同向滚动；库选择由系统 Spinner 换成
  Material 3 暴露式下拉，范围由两个 CheckBox 换成带标签的开关行，「切换间隔」标签与数值分离、整行可点；
  空库时给出空状态引导；「切换桌面 / 切换锁屏」常驻壁纸页底部，添加壁纸改为右下角悬浮按钮；
  新建库常驻顶栏图标、删除库收进溢出菜单；标题仍显示「应用名 v版本号」。功能逻辑零改动。
- **v3.1**：壁纸列表改 2 列网格（1:1 圆角缩略图 + 标题 + 删除，整卡可点开预览；缩略图加 4MB
  内存缓存，避免网格滚动时反复解码掉帧）；全部弹窗改用 Material 3 圆角弹窗 + 描边输入框；
  裁剪页加手势操作提示与独立底部操作条；新增深色模式（跟随系统，含 values-night 配色与系统栏图标明暗）。
- **v3.2**：取消底部设置 Tab，改为从左侧滑出的设置抽屉（宽 300dp、右侧圆角，非全屏；点顶栏
  左上角图标或从屏幕左缘右滑打开），收起状态即壁纸库。顶栏标题改为「当前壁纸库名字」，版本号
  移到抽屉顶部版本行。壁纸列表由 2 列网格改为单列长条：缩略图缩成 44dp 小方块、行内以标题文字
  为主，去掉每项里的小删除按钮，改为**左滑露出右侧删除按钮**（左滑滑过一半吸附展开，同一时间
  只允许一行展开，列表滚动会自动收起）。预览弹窗的标题直接就是壁纸标题，点标题即可改名（不再
  需要「改标题」按钮）。「切换桌面 / 切换锁屏」两个按钮合并为一个：当前库范围只有桌面或只有
  锁屏时点击直接切换，两个范围都勾时先弹范围选择。
- **v3.3**：`CropView` 初始化做防御性加固（预防性改动，不是修已发生的 bug）。`resetLayout()` 是唯一
  设置 `minScale`/`maxScale`/`matrix` 的地方，而它在「位图或视图尺寸未就绪」时直接 return —— 这个
  提前返回在启动时必然发生一次（`setBitmap` 在 `onCreate` 里调用，此时视图尺寸还是 0），正常靠随后的
  `onSizeChanged()` 补救。加固做的事是：用 `matrixReady` 记录就绪状态，并在 `onDraw`、`onTouchEvent`、
  `export()` 三个入口做幂等兜底初始化，万一那次补救没发生也不会退化成「捏合被钳死在 1 倍 + 拖动挪不动
  + 导出等于原图」这种不崩溃不报错、极难定位的状态。正常路径下行为不变（初始化成功后兜底调用全是空操作）。
- **v3.4**：修复「裁剪页预览效果 ≠ 实际上屏效果」。裁剪取景框高度原本是「屏幕高 − 顶部提示 − 底部按钮条」
  （约 1080×1900，比例 0.568），而壁纸上屏区域是整屏（1080×2400，比例 0.45）；引擎绘制时会对存储图做一次
  **居中裁剪铺满**（`WallSwitchService`），于是上屏后左右各被再裁掉约 142px、整体被放大 1.263 倍 ——
  裁剪页看到的完整宽度与实际不符。改为**裁剪区铺满整屏**、提示与按钮改为浮层（不再占用布局高度），
  系统栏避让只施加在浮层容器上。这样导出图比例 = 屏幕比例 = 壁纸上屏区域，那次居中裁剪变成空操作
  （scale = 1），所见即所得。
- **v3.5**：裁剪页右上角新增两个「桌面图标预览」开关，用来判断构图主体会不会被桌面图标挡住。
  左（网格）= 内置示意网格：状态栏与 Dock 的纵向位置用真实系统栏 inset 计算，列数按实测的 4 列
  （格宽 = 屏宽/4，图标在格内居中），行数由可用高度推算 —— 无需准备，但只是近似。
  右（图片）= 选一张自己的首页截图叠加：截图与取景框同为整屏同比例，按 centerCrop 铺满后像素对齐，
  完全准确。两者都不可点击、不拦截触摸，开着也能正常捏合与拖动。只加在裁剪页：预览弹窗里的图是按
  自身比例 fitCenter 显示的，叠图标格几何不对。
  实测结论（依据一张系统裁剪器的首页预览截图 1264×2800 做像素分析）：壁纸确实铺满整屏、四周无留白
  （验证 v3.4「取景框 = 整屏」方向正确）；图标格是 4 列而非 5 列；图标只占中间偏下一条带
  （行中心约 0.476 / 0.595 / 0.714 屏高，行距约 0.119），顶部是时钟天气小组件；系统预览未绘制 Dock，
  因此 Dock 与真实排布仍需用截图模式在你机器上核对。

- **v3.6**：首页截图叠加层改为**先抠图再叠加**。v3.5 直接把整张截图半透明盖上去，截图自带的壁纸也
  跟着叠了一层，两层壁纸混在一起发灰。现在只保留图标与文字：判据是**局部细节强度**（图标与文字有
  锐利边缘和内部细节，壁纸是平滑渐变）—— ① 3×3 均值模糊去掉 JPEG 压缩噪点（否则 8×8 块噪声会被
  误判成边缘）；② 取与 8 邻域的最大亮度差，线性映射为不透明度；③ 5×5 最大值膨胀填满图标内部的
  平坦区域，否则纯色图标会只剩一圈描边。工作分辨率长边 720，纯像素运算放在后台线程，解码后约几百
  毫秒。算法先用一张真实首页截图离线跑通并肉眼确认抠图效果后才写进代码。
  同时把首页底图提升为**全局设置**：在设置抽屉新增「桌面图标预览」卡片，选一次即可（点按选/换、
  长按清除），抠好的图层存到应用私有目录；之后每次进裁剪页直接读取，不再需要每设一张壁纸就重选一次。
  在裁剪页里临时选图也会顺手存成全局底图。- **v3.7**：新增「导出目录」（SAF，ACTION_OPEN_DOCUMENT_TREE）。设置抽屉里选一个文件夹
  （如 Documents/wallswitch），之后每导入一张壁纸会自动把**全图按原始字节**复制过去
  （不解码、不重压，零画质损失）；另有「立即导出全部壁纸」把库里已有的图一次性导出。
  文件卸载后仍保留、可用文件管理器直接查看，且**不会出现在系统相册**里（这是相对 MediaStore
  方案的选择理由）。注意：卸载重装后持久化授权会失效，需要重新点一次选目录，但已导出的文件还在；
  插件不会自动把已导出的文件搬回库里，需要重新添加。- **v3.8**：修复「解码分辨率被 2 的幂采样砍掉一大半」这个上屏发虚的根因。实测一张 6736×8981 的原图
  入库后只有 700×1550（屏幕 1264×2800，仅 55%），上屏等于放大 1.8 倍。原因链：`calcSampleSize`
  用的是「一旦低于上限就停」的 2 的幂，8981 的源图 sample=4 → 解成 1684×2245，60MP 的信息在解码
  那一步就扔掉 94%；用户再在裁剪页放大一点，可用真实像素更少。改为「只要再放粗一倍仍不低于目标
  分辨率就继续放粗」，保证解码结果不小于目标；裁剪源图改走新增的 `decodeCropSource()` —— 在像素
  预算内取**最小**的 2 的幂采样，且解码后**不再二次缩小**（原来的 `decodeBounded` 采样后还会
  `scaleToFit` 缩到一个固定上限，等于把预算里还剩的清晰度又扔掉一次）。采样受堆预算约束
  （maxMemory/16 像素、封顶 24MP）防 OOM，Manifest 申请 `largeHeap`，并让 `scaleToFit` 缩放后
  立即回收原图，避免瞬时持有两份大位图。导出上限仍是屏幕长边。
  另外「桌面图标预览」去掉了内置示意网格，只保留精确的截图叠加：网格的列数/行距只能靠猜
  （写死的 4 列是从一张首页截图量出来的），换设备或换桌面布局就不准；而截图叠加按整屏同比例
  对齐，像素级准确，裁剪页右上角因此只剩一个开关。- **v3.9**：四件事一起。
  ① 裁剪页源图解码挪到后台线程：页面立刻显示、中间显示「加载中…」，解码期间「确认」置灰
     （否则点了会因为没图而报「保存失败」），「取消」照常可用。
  ② 导出改成**区域解码**（`BitmapRegionDecoder`）：拿着当前取景框的矩形回原图文件取那一块，采样取
     「该区域最长边 ≥ 屏幕长边」的最小 2 的幂 —— 于是**放大多少倍都输出满屏幕分辨率**，不再依赖
     事先猜测的放大余量；取不到区域（格式不支持等）时回退到原来的「从内存位图裁」。
  ③ 裁剪页去掉右上角按钮，改成**单击取景区**切换桌面图标预览；`CropView` 里区分轻点与拖动/缩放
     （位移 < touchSlop 且 < 300ms 才算轻点）。
  ④ 上屏链路收敛：**桌面只走动态壁纸引擎**，删掉静态 `setBitmap` 的三道/四重校验与延迟重试
     （那套是给桌面「幽灵图」兜底的，引擎架构上不存在该问题）；引擎未激活时桌面**不做任何切换**，
     只提示去打开引擎开关。**锁屏保留一次 `setBitmap(FLAG_LOCK)`** —— 引擎只认「系统壁纸」这一件事，
     同时盖住桌面和锁屏、无法单独控制锁屏，所以锁屏要独立设置只能走这次静态调用；桌面与锁屏因此
     仍可各自独立设置。新增全局「启用动态壁纸引擎」开关（引擎卡片里，替换原来的按钮）：真值取
     **系统实际状态**（`WallSwitchService.isActive`）而不存偏好值 —— 否则你在系统选择器里点了取消，
     开关还显示「开」而点切换毫无反应；打开时先把当前桌面壁纸存到 `files/previous_wallpaper.png`
     再拉起系统选择器（普通 App 没有 `SET_WALLPAPER_COMPONENT` 权限，必须用户确认一次），
     关掉时把存档设回去（`setBitmap` 会同时解除动态壁纸），没有存档则 `clear()` 退回系统默认。
